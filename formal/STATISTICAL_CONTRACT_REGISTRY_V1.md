# Air Slot Statistical Contract Registry V1

Status: `SCIENTIFIC_MAINTENANCE_DOCUMENTATION_ONLY`

This registry identifies the estimand-specific statistical contracts confirmed
in Phase B2. Shared helper names do not imply that experiment-specific
statistics are interchangeable. No experiment, bootstrap, aggregation, or
artifact is regenerated by this document.

## Common Cluster-Resampling Contract

`exp/shared/resampling.py` owns the common mechanics:

- the resampling unit is the original episode;
- episode identifiers are sorted before a fixed-seed plan is drawn;
- sampling is with replacement;
- repeated draws are retained as distinct bootstrap occurrences, not collapsed;
- each occurrence receives a `bootstrap_instance_id` and a technical node ID;
- `original_episode_id` remains the identity used to prevent an original
  episode from pairing with itself.

The frozen Final Test computations recorded in the B1 reconciliation used seed
`20260906` and 2,000 completed episode-bootstrap replicates. Those values are
run-contract facts, not permission to rerun or alter a frozen analysis.

## Ranking And Selection Contracts

`exp/exp2/metrics.py:midrank_percentiles` uses average ranks and returns
`(rank - 0.5) / N`. `top_k_ids` orders finite scores descending and then uses
the technical node ID as an ascending tie-breaker.

| Analysis | Ranking population | Selection / comparison population | Do not substitute with |
| --- | --- | --- | --- |
| Exp2 | Its ranked eligible base sample | Overall priority comparison on Exp2's common-support conditional summaries | Stage-local ranks. |
| Exp3 | Each eligible stage separately, including each bootstrap draw | Stage-local agreement and similar-delay heterogeneity | Exp2 overall ranks. |
| Exp4 | Each stage's supported canonical events | Capacity screening and eight-view consensus | Six-view aggregation robustness. |
| Aggregation robustness | Each replicate and each of six aggregation views | Six-view robustness estimates | A single stored Exp4 rank or an Exp2 rank. |

The Exp4 `_top` implementation repeats the valid-input ordering rule used by
`top_k_ids`, but has its own return shape and input guards. It is not the
authority for Exp2's rank outputs.

## Similar-Delay Contracts

All three analyses use a related eligibility predicate: nodes must be in the
same operating stage, originate from different original episodes, and have an
absolute predicted-delay gap no greater than the stated caliper. Candidate
node-pair gaps are balanced by taking a median within each episode pair before
the episode-pair result is summarized.

| Analysis | Implementation role | Statistical object | Material distinction |
| --- | --- | --- | --- |
| Exp2 | `exp/exp2/similar_delay.py` reference builder plus cached bootstrap backend | Overall priority separation, including component gaps | Uses its already overall-ranked base sample. |
| Exp3 | `exp/exp3/analysis.py` reference and vectorized pair builders | Stage-specific heterogeneity; median and p90 percentile gaps | Re-ranks within each eligible stage and bootstrap draw. |
| Aggregation robustness | `validation/materialize_aggregation_robustness.py` pair universe plus Python/Numba bootstrap backends | Per-view similar-delay robustness across six views | Re-ranks each view in each replicate; production path may use Numba. |

The default primary caliper is 5 minutes. Where 10- and 15-minute variants are
materialized, they are sensitivity settings rather than a replacement primary
estimand. Reference and optimized backends must preserve original-episode
exclusion, occurrence multiplicity, ranking population, pair balancing, and
the stated aggregation statistic.

Fixed-draw tests cover Exp2 reference versus optimized behavior and Exp3
reference versus vectorized behavior. Aggregation view formulas and frozen
BASE reproduction are checked. A future aggregation backend change needs a
direct Python-versus-Numba pair/replicate parity test before it can be treated
as equivalent; this registry does not claim such proof for every input.

## Confidence-Interval Contract

All current confidence intervals use 2.5% and 97.5% empirical quantiles over
bootstrap output, but nonfinite handling differs:

| Utility | Treatment of `None`, NaN, and infinity |
| --- | --- |
| `exp/shared/resampling.py:interval` | Coerces values and removes all nonfinite values. |
| `exp/exp2/bootstrap.py:percentile_interval` | Removes `None`; NaN/infinity remain in the numeric array. |
| `validation/materialize_aggregation_robustness.py:_interval` | Removes `None`; NaN/infinity remain in the numeric array. |

For finite, nondegenerate draws these produce the same percentile rule. They
must not be silently interchanged for a future incomplete or nonfinite draw.

## Maintenance Rules

1. Define a future statistic by its unit, ranking population, support filter,
   pair identity, bootstrap expansion, and interval treatment, not by a helper
   function name.
2. Preserve reference implementations as scientific oracles when optimizing a
   backend; add fixed-draw parity evidence before replacing an active backend.
3. Do not pool Exp1--Exp4 bootstrap code merely because they share episode
   resampling mechanics. Their estimands differ.
4. This registry records boundaries only and does not authorize a post-freeze
   rerun, resampling, or consolidation.
